The console lists the most recent runs and there is no way to look further back. A month-end review
needs more than the last page, and right now the only answer is to query the service directly.

Give the reader a way to see older runs.

Understanding

This is a feature request, not a bug. The console (apps/console/app/page.tsx) calls listRuns(50) → GET /runs?limit=50 → the ingest service's in-memory Store.Runs() returns all runs newest-first, then the HTTP handler (services/ingest/http.go:19-35) slices the first N (default 50, max 200). There is no offset, cursor, or date-range parameter on the API, and the console page has no pagination controls or date filter form.

The constraint "Nothing is deleted or expired" means the fix is a read-side change only — add a query parameter to GET /runs and UI to use it.

Two prior implementations exist, both closed without merging:

PR Add offset-based pagination to the run list #346 — offset-based pagination (?offset=, ?limit=, Previous/Next links)
PR Keep runs for longer than the console can show — date range filter, not pagination #355 — date range filter (?startedAfter=, ?startedBefore=, date input form)

The factory issue file (.factory/issues/07-retention-window.md) carries route: plan-revision and the issue body says "The plan a person accepted is the plan that was built" — meaning a person should decide which approach to build before code is written.

No related open issues or duplicates found. Issues #353, #344, #336, #328 are all closed with similar titles.

services/ingest/run.go (the Store — note the factory issue says store.go but that file doesn't exist; the store lives in run.go)
services/ingest/http.go (the HTTP handler)
apps/console/lib/ledger.ts (the TypeScript client)
apps/console/app/page.tsx (the Next.js page)
