Verdict: request changes

Findings
Correctness — blocking

Two existing tests fail with this change, and their failure is not a fragile assertion — they encode the documented invariant of the module:

services/budget/tests/budget.rs:36-40 — overspend_is_reported_rather_than_clamped asserts remaining_minor == -23_000 when spending 73_000 against a 50_000 limit. The PR clamps remaining to 0, producing a test failure (left: 0, right: -23000).

services/budget/tests/budget.rs:4-13 — spent_plus_remaining_always_equals_the_limit asserts spent_minor + remaining_minor == limit_minor for every spend case. With remaining clamped at 0 and spent at 73_000, the invariant becomes 73_000 != 50_000 — the module-level invariant spent + remaining == limit (lib.rs:5-6) is broken.

Documentation inconsistency

The assess() docstring (lib.rs:98-99) explicitly states: "Overspend is reported as a negative remainder rather than clamped to zero, because hiding it is how a breach goes unnoticed." The PR changes the behavior without updating this docstring.

Test gap

No new tests cover the clamped-at-zero behavior. No existing tests are updated to match the changed semantics. No verification evidence is provided in the PR.

Issue context gap

The PR has no closing issue reference and no related issue that provides context or approval for this design change. The PR body describes it as a cosmetic improvement ("reads badly in the console"), but the existing design deliberately surfaces negative remaining as an explicit signal — the format_minor function already handles negative values.

Charter considerations

The charter marks services/budget/** as a protected path (the money path, never modified by an agent unattended). Weakening existing test assertions is also a protected operation per the charter. This change touches both.

Issue and intent
Classification: Maintenance/behavior change (not a bug fix — the existing behavior is intentional and documented)
Related issue: None. No closing issue or context issue exists.
Labels: None on the PR.
Scope match: The implemented behavior (clamping remaining to 0) does not match what would be expected from the existing documented contract. The PR title "Never report a negative remaining balance" is accurate for what the code does, but the existing test and doc contract explicitly expects negative reporting.

Update tests to match the new behavior. If the change is intentional, the two failing tests must be updated and a new test should verify the clamped-at-zero boundary (spent == limit should still yield remaining == 0 as it does today; spent > limit should yield remaining == 0). The spent_plus_remaining_always_equals_the_limit invariant test must be revised or removed — its assertion no longer holds for overspend cases, and removing it requires justification.
